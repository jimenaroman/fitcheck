The fit checker, as a transit map

Three routes run through one system. Line A is what happens every time you check a posting. Line B is how you prove it works. Line C is how your resume changes without breaking anything.

Station Shared station: other lines stop here too
A

Check a posting

Runs live, every time you paste a job

  1. React app on Cloudflare Pages

    Paste the posting

    From your phone or laptop. Installed on your home screen as a PWA.

  2. FastAPI on Railway

    Receive and fence it off

    Wraps the posting text in delimiters and labels it as data, so hidden instructions inside a posting are treated as text, not commands.

  3. Claude Haiku or Gemini Flash

    Extract requirements

    Splits the posting into required, preferred, and non-skill items like graduation date. Called through your own provider wrapper, so models are swappable.

    Line B stops here
  4. Pydantic

    Check the shape

    Rejects output that doesn't match the schema. One retry, then "review manually" instead of looping forever.

    Line B stops here
  5. Claude Haiku or Gemini Flash

    Match each requirement

    Points each one to a resume item ID with a supporting quote, or marks it as a gap. Contact info is never sent.

    Lines B and C stop here
  6. Plain Python

    Verify the evidence

    Every quoted line must actually exist in the item it cites. This catches invented matches.

    Line B stops here
  7. Plain Python

    Score and decide

    Counts required coverage. Missing two or fewer out of ten means apply. No AI touches the math.

    Lines B and C stop here
  8. Postgres on Railway

    Save everything

    Postings, requirements, matches, and a run log with model, tokens, cost, and latency.

  9. React app

    See your results

    Your score, the exact gaps, and a running tally of which missing skills block you most often.

B

Run the eval

Runs on your laptop, whenever you change a prompt or model

  1. GitHub repo

    Load the answer key

    eval_resume_v1.yaml plus labeled postings you marked by hand.

  2. Same stations as Line A

    Run the pipeline

    Once with a top model as the baseline, then with Haiku and Gemini Flash.

  3. pytest

    Grade against the key

    Extraction recall, false matches, false gaps, and whether the apply decision agrees with yours.

  4. Report

    Compare the results

    Accuracy against cost and speed, per model. This is your interview slide.

C

Update your resume

Runs whenever you edit resume.yaml

  1. resume.yaml in GitHub

    Edit your live resume

    Add a project, reword a bullet, change a tag.

  2. Lines A stations

    Recheck saved postings

    Rerun matching and scoring on everything you've already saved.

  3. React app

    See what shifted

    For example, "Lyft: 6 of 10 required, now 8 of 10."

Two resumes, two jobs

resume.yaml

Your real, living resume. Edit it anytime. Lines A and C read it. This is what gets checked against real postings.

eval_resume_v1.yaml

The resume your answer key was written against. Never edited, and only Line B reads it. If it changed, correct answers in the key would suddenly look wrong.
