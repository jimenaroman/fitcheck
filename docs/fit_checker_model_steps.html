What the model reads, and what it decides

The model makes two narrow judgments: what a posting asks for, and how a resume line relates to it. Code turns those judgments into Have, Weak, or Gap using a table you control. Changing a rule means editing one cell, not rewriting a prompt.

Part 1: what gets pulled from a posting

Extraction reads the qualifications and eligibility lines, and ignores the rest.

Read

  • Minimum, basic, or required qualifications
  • Preferred qualifications, "nice to have," "bonus"
  • Eligibility lines anywhere: graduation dates, degree, work authorization, location

Skip

  • About the company, mission statements
  • Benefits, salary, perks
  • Equal opportunity statements, application instructions

Responsibilities You decide

"You will build REST APIs and deploy services on AWS." These aren't listed as requirements, but they describe the actual job. Options: skip them, count them on the leaderboard only, or score them like preferred items.

The four requirement types

The type tells the matcher how specific your evidence must be. This is your principle from calibration: the more specific the posting, the more specific the evidence.

TypePosting wordingExamples
categoryNames a field, not a tool"Web development," "data analysis," "machine learning"
named_toolNames specific tools or languages"React," "Tableau or D3," "Java"
knowledgeAsks what you understand"Knowledge of statistics," "understanding of data structures"
hands_onAsks what you've built or run"Experience building data pipelines," "have shipped a web app"

Part 2: how the model decides whether a skill exists

  1. The model receives one posting's requirements and your resume items ModelEach resume item has its ID, text, and whether it's a bullet, a course, or a skills-list entry. Contact info is never included. Posting text is wrapped and labeled as data.
  2. For each skill, it picks the best evidence and quotes it ModelOne resume item and an exact quote, or "none."
  3. It labels how the evidence relates to the requirement ModelOne of the seven relations below. When unsure between two, it picks the weaker one, because false matches are worse than false gaps.
  4. Code verifies the quote CodeThe quote must appear word for word in the cited item (R4, R5).
  5. Code looks up the status in the table CodeRequirement type × relation gives Have, Weak, or Gap.
  6. Code applies the last checks CodeSkills-list-only evidence becomes Weak (R7). A years requirement without a stated duration caps Have at Weak (R9). And/or combines the skills (R3). Every result gets a reason code, like listed_not_shown, so the app can explain it.

The seven relations

RelationMeaningExample
exactThe resume shows the skill itself, or a clear instance of the category asked forpandas for "pandas"; Streamlit app for "web development"
same_categoryA different tool that does the same jobPlotly for "Tableau or D3"
smaller_scaleRelated work, smaller than what's askedCSV cleaning for "data pipelines"
taughtYou taught the skilltutoring for "Java"
courseworkA course covers itLinear Algebra for "knowledge of linear algebra"
different_techniqueSounds related, but it's a different methodRule-based detector for "machine learning"
noneNothing on the resume supports itAnything for "Kubernetes"

What the model returns for one skill

{
  "requirement_id": "req-4",
  "skill": "tableau",
  "evidence_id": "proj-finance-b2",
  "quote": "Drew Plotly monthly budget charts",
  "relation": "same_category",
  "reason": "Plotly is a visualization library, but not Tableau"
}

Code checks the quote, looks up named_tool × same_category, and gets Weak. The model never outputs a status, so it can't talk its way to Have.

Why it's split this way

BenefitHow
You own the policyEvery status comes from a table cell you approved, not from the model's opinion
Rules change cheaplyDisagree with a cell? Change one line of Python. No prompt edits, no retesting the model
Evals get sharperYour labels can record the relation too, so the eval shows whether the model misread the resume or the table gave the wrong status
Interview story"The model labels facts, the code applies policy" is a clear, defensible design
